# /brainstorm

Argument: the problem or question to ideate on.

## Steps

1. **Frame**: state the need one level above the requested artifact; list hard constraints; explicitly suspend soft ones ("we've always done X") for the session. An existing favored solution gets written down and set aside visibly.
2. **Generate — no judging**: 15–30 numbered ideas, one terse line each (long descriptions are evaluation in disguise). The first five are everyone's ideas; push past comfort. Stalled → switch angles: invert (how would we guarantee failure? reverse each) · extremes (10x budget / $0 / ship tomorrow / 1 user / 1M) · perspectives (security engineer? game designer? nature? a market?) · decompose & recombine · analogy (who has the structurally identical problem?) · remove the sacred part.
3. **Converge — explicit judging**: cluster into families (a one-member cluster is often the interesting one) · state criteria before scoring (impact, cost, reversibility, fit) · shortlist 2–4 genuinely different candidates (best of each family, never top-four-of-one) · kill with one-line reasons (flag "killed by soft constraint" for revisit) · salvage hybrids before discarding ("A's mechanism with B's interface").
4. **Hand off**: shortlist with one-line cases · the criteria used · the kill list · the cheapest falsifying test per candidate. Real stakes → /architect. A brainstorm never silently becomes a commitment.
5. Rules: zero evaluation during generation (one "that won't work" reshapes everything after) · strong-opinion inputs go in last · paraphrases don't count (mechanisms must differ) · timebox both phases · keep the discards.
